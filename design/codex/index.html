RECOMMENDED
STARTING POINT

A1 Attention rail + H1 Compact identity + S1 Workspace tree.
Then M2 Recall in place + M5 Memory health. Add M1 Context receipt when session-level read events can support it.

01 / Attention

A1

Attention rail

A persistent summary keeps the terminal grid visible and gives attention a predictable home.

Risk / Counts omit the question itself; opening a pane still costs a context switch.

A2

Attention palette

Search and keyboard selection make occasional triage fast without occupying the workspace.

Risk / Hidden until invoked; new users may miss agents waiting for input.

A3

Triage stack

Persistent task previews let you choose the next interruption before entering its terminal.

Risk / The extra column reduces terminal width, especially with twelve panes.

02 / Pane identity

H1

Compact identity

A stable pane number and compact context line identify the task without enlarging the 32px header.

Risk / Long task and branch names compete for the same horizontal space.

H2

Task first

A task-first context strip makes task and branch legible while the native header stays 32px.

Risk / The separate 42px context strip consumes more terminal height.

H3

Fixed identity dock

Fixed pane numbers connect a dense grid to one shared identity dock for the selected pane.

Risk / Unselected task details are hidden until focus changes.

03 / Sidebar

S1

Workspace tree

Repository and worktree ownership stay explicit as agents change state.

Risk / Deep nesting truncates names; collapsed branches can hide waiting panes.

S2

Triage groups

Grouping by needs-you, unread and working turns navigation into a work queue.

Risk / Rows move when state changes, weakening spatial memory.

S3

Agent roster

Agent groups suit workflows where each assistant has a known role.

Risk / Repository ownership is weaker and urgent work can be buried in another agent group.

04 / Memories

M1

Context receipt

See the exact decisions retrieved and saved by this session, with source and version.

Risk / A retrieved memory does not prove the agent applied it.

M2

Recall in place

Find and prepare a decision for one agent without leaving the terminal grid.

Risk / Wrong target pane or excessive context can undo the benefit.

M3

Decision beside the question

Answer a repeated question with the current decision and its reason.

Risk / A similar question may require a different decision on this branch.

M4

Branch brief

Read what teammates learned on this branch before taking the next step.

Risk / Private notes must never enter a team brief by implication.

M5

Memory health

Distinguish local memory, session bridge and cloud sync without visiting Settings.

Risk / A green session bridge cannot certify memory reads or writes.

M6

First real reuse

Show the first cross-agent retrieval of an actual project decision.

Risk / Demo activity or a retrieval must not masquerade as verified application.

05 / Workspace

W1

Result with evidence

Separate a quiet agent from a change that is ready for review.

Risk / Test results become stale as soon as the checked files change.

W2

Shared worktree awareness

Expose two agents editing the same checkout before people overwrite each other.

Risk / Being in the same checkout is only a risk signal, not proof of a file conflict.
