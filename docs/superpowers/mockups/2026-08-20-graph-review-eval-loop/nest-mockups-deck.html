How it flows the whole story on one screen

🎫 Source

A ticket lands (Jira / Linear / GitHub / @Nest). You pick a graph template and hit run.

→

🕸️ Graph orchestrates

architect → coder → N reviewers → gate → tester, each a real CLI in a shared worktree. Handoff by artifacts.

→

👁️ You evaluate optional

Open the run in the editor: diff + reviewer concerns inline. Or let it run full-auto.

→

✓ Decide

Approve → open PR. Request changes → feedback re-injected, the graph re-runs.

↻ Full-auto path: if you leave the run autonomous, the gate resolves on the reviewers' verdicts and it goes straight to Decide — no human stop. Visualizing is opt-in, per your call.

La idea macro: orquestás agentes en grafo, y el review-en-el-editor es la capa que cierra el círculo. Es lo que Slack Code hace en el chat (pero solo mirar) y vos hacés en un IDE real (mirar + editar + orquestar).

Autonomous vs Review opcional del programador

Run mode · #482 rate-limit retries

🤖 Full auto

The graph runs end-to-end. The gate resolves on the reviewers' verdicts; a clean run opens a PR by itself. You get a notification, not a stop.

👁️ Review at gate selected

Runs autonomously until the gate. Then it waits for you to evaluate the diff + concerns and decide. Best of both: hands-off until it matters.

🔎 Review every node

You approve each stage's handoff before the next agent starts. Maximum control, for high-stakes changes.

⚙️ Default

Set a per-repo default so new runs inherit it. Override per run from here or the board.

Esto responde tu "opcional": el programador elige dejar full orquestado o visualizar/intervenir. Por run o como default por repo. El "Review at gate" es el punto medio que cierra el eval-loop sin frenar todo.

The eval loop closes the gap the market asks for

At the gate

Each reviewer wrote a verdict artifact. Nest reads it to set the gate — this is what turns "the graph just runs" into "the graph verifies".

.nest/graph/review-security.json
"blocking": true,
"concerns": [ "idempotency key reused…" ]
→ gate = blocked → waits for your call ↓

✓ Approve

  1. Open PR (or merge) from the run's branch
  2. gate marked passed → tester node runs
  3. run archived, team notified in Slack

↻ Request changes

  1. your feedback re-injected into the coder node
  2. the graph re-runs that branch in the same worktree
  3. back to the gate with a fresh diff

Esto es "evaluation frameworks" — la 4ª palabra del aviso que hoy tenés escrita pero sin cerrar. El humano (o el verdict de los reviewers en full-auto) lee el veredicto → bloquea o pasa el gate. Aprobar abre PR; pedir cambios re-corre el graph. El círculo entero: orquestar → producir → revisar → evaluar → decidir.
